# docs/wiki の更新ルール

この wiki は、Atlas(リアルタイム対戦のモンスター収集ゲーム)の仕様と設計を、develop の実装に合わせてまとめたもの。
人と LLM の両方が読み、更新する。LLM は [index.md](index.md) から読み始め、必要なページだけを開く。

## エリア

| エリア | 内容 |
|---|---|
| `game/` | ゲームの内容とルール(仕様)。API・DB・クラス名は書かない |
| `conventions/` | Client・APIサーバー・バトルサーバーに共通する決まり(命名・ID・nullable・`player_diff`・アイテム・業務エラー) |
| `server/` | APIサーバー(Rust)。構成と、各 API の振る舞い |
| `db/` | MySQL のテーブル |
| `master-data/` | マスターデータの生成・配布・テーブル |
| `client/` | Unity クライアント |
| `battle-server/` | バトルサーバー(C#/MagicOnion)と、共有の `Atlas.BattleCore`・`Atlas.BattleContracts` |

## 何が正か

| もの | 正の置き場所 | 扱い |
|---|---|---|
| クライアント向けと内部の API の形(RPC・メッセージ・`idempotency_level`) | `Shared/proto/` の `.proto` とそのコメント | wiki には振る舞いと理由を書き、フィールドの表は写さない |
| 業務エラー(reason・action) | `Shared/errors.toml` | 同上 |
| マスターデータの列と件数 | `Shared/master-data/`(スキーマと CSV) | |
| 型・関数の細かい説明 | コードのドキュメントコメント | wiki には、どれを何に使うかと組み込み方だけを書く |
| ゲームのルール・方針・理由 | この wiki | 手で書く。LLM は下書きしてよいが、人がレビューする |
| 決まっていないこと | [open-questions.md](open-questions.md) | 決まったら、ここから消して該当ページに反映する |

### wiki と各 CLAUDE.md の分担

| 置き場所 | 書くこと |
|---|---|
| wiki | 構成・設計・理由(人が読むもの) |
| 各プロジェクトの `CLAUDE.md` | 作業のルール(命名、コメント、やってはいけないこと、ビルドの注意、生成物の扱い)。構成の説明は書かず wiki にリンクする |

- コーディング規約は `CLAUDE.md` に置く。`CLAUDE.md` は作業のたびに自動で読み込まれるが、wiki はリンクを開かないと読まれないため
- 理由のある規約は、ルールを `CLAUDE.md` に1行で書き、理由を wiki に書く(同じ説明を2か所に書かない)

コードと wiki が食い違っていたら、コードを正として wiki を直す。コードのほうが間違っていそうなときは、直す前に人に確認する。
`docs/game-spec.md`・`docs/design.md` はこの wiki の元になった文書で、wiki と食い違うときは wiki(= 実装)を正とする。

## ページの形

- 1ページ1テーマ。先頭に frontmatter を置く
  - `title`、`status`、`area`(必須)
  - `related`: 関連するページ(wiki のルートからの相対パス、拡張子なし)
  - `proto`: そのページが説明する `.proto`(リポジトリのルートからの相対パス)
  - `code`: そのページが説明するコード(リポジトリのルートからの相対パス。フォルダでもよい)。コードを変えたときに、
    直すべきページを探すのに使う
  - `updated`: 最後に内容を変えた日
- `status` の値
  - `confirmed`: 確定
  - `current`: 当面の方針(実装済みだが、あとで変わり得る)
  - `planned`: 追加予定(仕様だけ決まっていて、実装が無い)
  - `open` / `index`: 未確定の一覧 / 目次
- **`status` を `confirmed` にするのは人が決める**。LLM は自分の判断で `confirmed` にしない
- 他のページへの参照は相対リンクにし、リンクの文字はページ名にする(`[マッチング](../server/matchmaking.md)`)。節番号は使わない
- 実装が無いものは、ページか節の見出しに「(追加予定)」、API はあるが画面が無いものは「(画面は未実装)」と書く

## コードを変えたとき

1. 変えたコード・`.proto` を `code:`・`proto:` に持つページを探す(`grep -rl "<パス>" docs/wiki`)
2. そのページの内容が変更後も正しいか確かめ、ずれていれば直す。`updated` を更新する
3. 実装の中で新しく決めたことは、該当ページに書く
4. [open-questions.md](open-questions.md) の項目が決まったら、その行を消し、決めた内容を該当ページに書く
5. ページを足したら、該当エリアの `index.md` と、ルートの [index.md](index.md) の一覧に足す

## 書き方

- 日本語で書く。「何をするか」に加えて「なぜそうするか」を書く(判断の理由が、この wiki の価値)
- 検討して採用しなかった案は、理由とともにそのページの末尾の「採用しなかった案」に残す
- 実装名(クラス、ファイル、テーブル、RPC)は `コード書式` にする
- 数値や名前は、コード・`.proto`・マスターデータにあるものと一致させる。確かめられないものは書かずに
  [open-questions.md](open-questions.md) に足す
- コードのコメントからこの wiki を参照しない(ルートの `CLAUDE.md` のコメントのルール)。wiki からコードを参照するのはよい
